# RFC-001 — Первая версия Simulation

Предлагаем начать с карты 20×20, неподвижных препятствий, двух станций,
одного робота и одного задания доставки. Несколько роботов и поломки — следующие
этапы. Редактирование работающей карты не требуется по ТЗ; восстановление запуска
после перезапуска — дополнительная возможность вне текущего объёма.

## Устройство

Один постоянно работающий процесс `apps/simulation` обслуживает активные склады.
Для каждого склада он хранит состояние в памяти и последовательно обрабатывает
команды и шаги. Закрытие браузера не останавливает симуляцию.

| Часть | Ответственность |
| --- | --- |
| `packages/simulation-core` | Валидация, назначение задания, поиск пути, движение и переходы состояния; без таймеров и внешних подключений |
| `apps/simulation` | Состояние запусков, таймер, порядок команд, BullMQ, Redis, подтверждения истории и публикация снимков |
| API / PostgreSQL | Исходная карта, задания, запуски, результаты команд и история |
| Redis | Очереди сообщений и последний снимок для клиентов |
| renderer | Отображение карты, позиции и маршрута робота |

Ядро рассчитывает `step(state) → { nextState, events }`. Приложение решает,
когда вызвать шаг и когда опубликовать результат. Каждое перемещение робота
не требует отдельной задачи BullMQ.
