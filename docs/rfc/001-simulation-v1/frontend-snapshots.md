# Пример снимков для фронта

[К общему RFC](../001-simulation-v1.md) · [JSON с двумя снимками](frontend-snapshots.example.json)

Формат предлагается для согласования с API и renderer. Это пример данных для
разработки отображения, а не утверждённый контракт Socket.IO.
Имя события и runtime-схема сообщения здесь не задаются.

JSON содержит массив из двух полных снимков одного запуска. Каждый элемент —
отдельное обновление состояния; весь массив не является одним сообщением сервера.
Снимки соответствуют шагам 10 и 11 [сквозного примера доставки](delivery-example.md).
Груз уже получен, робот движется к станции назначения.

## Что находится в снимке

| Поля | Назначение |
| --- | --- |
| `warehouseId`, `runId` | Склад и конкретный запуск |
| `processNumber` | Номер процесса Simulation по ADR-003; не команда анимации |
| `snapshotVersion` | Версия опубликованного состояния внутри запуска |
| `tick` | Номер принятого шага расчёта; не время и не длительность анимации |
| `status` | Состояние запуска: в примере `running` |
| `map` | Полная исходная карта: размеры, препятствия, станции и начальная расстановка |
| `robot` | Текущая позиция, статус и перевозимый груз единственного робота |
| `task` | Станции задания, назначенный робот, статус, этап и ошибка |
| `route` | Оставшийся путь робота, без текущей клетки, с целью включительно |

`map.id` и `map.version` обозначают идентификатор и версию карты, упомянутые
в RFC как `mapId` и `mapVersion`. `map.initialRobot` — исходная расстановка;
для отображения текущего робота используется `robot.position`.

Версии 11 и 12 выбраны для примера, где начальный снимок имел версию 1 и пауз
не было. В общем случае `snapshotVersion` не вычисляется из `tick`: пауза меняет
версию состояния без нового шага расчёта.

## Как использовать два снимка

1. Загрузить JSON и показать первый элемент: робот стоит в `(4,1)` с грузом,
   маршрут состоит из `(4,2)` и `(4,3)`.
2. Передать второй элемент как очередное обновление. Для демонстрации можно
   сделать это через 500 мс; интервал относится к примеру, а не к формату сообщения.
3. Сопоставить робота по `id`, анимировать переход `(4,1) → (4,2)` и обновить
   оставшийся путь до одной клетки `(4,3)`.

Между снимками меняются только `snapshotVersion`, `tick`, `robot.position`
и `route`. Карта, груз и задание остаются прежними. Полная передача карты
не требует пересоздания её графических объектов при каждом обновлении.

Предлагаемые правила отображения для обсуждения:

- Первый снимок при подключении показывается сразу. Если загрузить только
  второй элемент, робот сразу стоит в `(4,2)` без проигрывания предыдущего движения.
- Для того же запуска повторные и более старые версии игнорируются.
- При переподключении или подтверждённом API новом запуске состояние показывается
  сразу, без анимации перехода из другого запуска или устаревшего состояния.
- При пропуске версий для первого варианта renderer можно сразу показать актуальную
  позицию. Оставшийся маршрут не является историей движения; анимация по прямой
  между далёкими позициями может провести робота через препятствия.

Плавность и длительность анимации выбирает renderer. Анимация не изменяет
серверную позицию и не завершает задание самостоятельно. Этот пример покрывает
одно перемещение одного робота; получение груза, завершение и ошибки описаны
в сквозном примере и потребуют отдельных примеров отображения.
