# Сценарии тестов движения

[Состояние и движение](state-and-movement.md) · [Сквозной пример](delivery-example.md)

Перед реализацией спецификация и тесты проходят человеческое ревью по ADR-002.

| Группа | Что проверяем |
| --- | --- |
| Вход | Размеры, целые координаты, границы, препятствия под началом/целью, ссылки на станции и правила начальных пересечений |
| BFS | Прямой путь, обход, тупик, узкий проход, запрет диагонали, края и углы, равные пути с фиксированным порядком соседей |
| Результат | Успех `found` с `route: []` отличается от `unreachable`; каждая клетка внутри карты и вне препятствий; переходы ортогональны; известная минимальная длина |
| Детерминизм | Один вход — один результат; поиск и шаг не изменяют входные объекты, часы и сеть не требуются |
| Доставка | Недостижимость каждой станции, получение перед сдачей, транзит через назначение без груза, нулевой участок, один груз |
| Шаг | Одна клетка за перемещение, расход первого элемента маршрута, отдельный переход погрузки/сдачи, точные данные событий из примера |
| Терминальные состояния | `completed` и `failed` больше не двигаются и не создают повторных событий; данные груза при ошибке согласованы со статусом |
| Управление запуском | Пауза сохраняет маршрут и груз; шаги не идут до подтверждения истории; повтор подтверждения не повторяет переход; исход сброса согласован с API |
| Следующий этап | Конкуренция за клетку, встречный обмен, неподвижный робот, занятая станция и окружение станции; после согласования служебного движения — приоритет следующего задания перед переходом на место ожидания и сохранение груза при переезде после ошибки; эти тесты не входят в реализацию одного робота |
