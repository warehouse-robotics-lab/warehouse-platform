# ADR-001 — Монорепозиторий на pnpm workspaces и Turborepo

- Статус — Proposed, подготовлено к ревью команды
- Дата — 2026-11-10

## Контекст

Команда начинает разработку Web, API и Simulation в одном репозитории. Нужны общие правила установки зависимостей и запуска команд, а также возможность параллельно инициализировать приложения.

## Рассмотренные варианты

- pnpm workspaces с рекурсивными командами pnpm.
- pnpm workspaces с Turborepo для выполнения задач и кеширования.

## Предложение

Использовать pnpm workspaces и локально установленный Turborepo. Запускаемые приложения размещать в `apps/*`, общие библиотеки — в `packages/*`. Использовать scope `@warehouse/*`.

Зафиксировать Node.js 24.22.2, pnpm 11.1.1 и Turbo 2.11.10. В корне определить команды `dev`, `build`, `lint`, `typecheck` и `test`. Каждый workspace-пакет объявляет только реализованные скрипты.

## Причины

- Разные приложения и общие пакеты развиваются в одном репозитории.
- Единые команды упрощают локальную работу и будущий CI.
- Turbo учитывает зависимости пакетов при сборке и позволяет кешировать результаты.

## Последствия

- Нужно поддерживать общий lockfile и версии инструментов.
- Выходные файлы и переменные, влияющие на результат задач, необходимо учитывать при настройке кеша.
- Настройки линтера и TypeScript для приложений уточняются при их инициализации.

## Открытые решения

Транспорт между API и Simulation, выбор контрактов, библиотеки отрисовки и размещение Simulation Core обсуждаются отдельно. Этот ADR фиксирует инструменты монорепы.
