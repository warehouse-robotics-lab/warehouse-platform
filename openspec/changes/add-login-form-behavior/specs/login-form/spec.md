# Spec Delta

## Purpose

Поведение формы входа: проверка полей, отображение ошибок,
ожидание результата и локальная тестовая отправка без API.

## ADDED Requirements

### Requirement: Обязательные поля

Поля почты и пароля MUST быть заполнены.
При отправке формы с пустым полем система SHALL показывать
под ним сообщение «Обязательное поле».
При ошибках полей тестовый обработчик MUST NOT вызываться.

#### Scenario: Оба поля пустые

- **WHEN** пользователь отправляет форму с пустыми почтой и паролем
- **THEN** под каждым полем отображается «Обязательное поле»
- **AND** тестовый обработчик не вызывается

#### Scenario: Почта не заполнена

- **WHEN** пользователь отправляет форму с пустой почтой
  и заполненным паролем
- **THEN** под полем почты отображается «Обязательное поле»
- **AND** тестовый обработчик не вызывается

#### Scenario: Пароль не заполнен

- **WHEN** пользователь отправляет форму с корректной почтой
  и пустым паролем
- **THEN** под полем пароля отображается «Обязательное поле»
- **AND** тестовый обработчик не вызывается

### Requirement: Обработка и формат почты

Перед проверкой и тестовой отправкой система SHALL удалять
крайние пробелы почты и приводить её к нижнему регистру
в соответствии с правилами user-account.

Почта, состоящая только из пробелов, MUST считаться пустой.
Для непустой почты система SHALL проверять формат адреса.
При неправильном формате под полем SHALL отображаться
«Введите корректную почту».
Тестовый обработчик при ошибке MUST NOT вызываться.

#### Scenario: Почта состоит из пробелов

- **WHEN** пользователь отправляет форму с почтой из одних пробелов
- **THEN** под полем почты отображается «Обязательное поле»
- **AND** тестовый обработчик не вызывается

#### Scenario: Некорректный формат почты

- **WHEN** пользователь отправляет форму с почтой userexample.com
  и заполненным паролем
- **THEN** под полем почты отображается «Введите корректную почту»
- **AND** тестовый обработчик не вызывается

#### Scenario: Нормализация почты

- **WHEN** пользователь отправляет форму с почтой
  «  User@Example.com  » и заполненным паролем
- **THEN** тестовый обработчик получает почту user@example.com

### Requirement: Обработка пароля

Система MUST передавать заполненный пароль тестовому обработчику
без изменения регистра, удаления пробелов и других преобразований.

Пустой строкой пароля MUST считаться только строка нулевой длины.
Дополнительные ограничения длины и сложности пароля в рамках
этого изменения не вводятся и требуют отдельного согласования.

#### Scenario: Пароль передаётся без изменений

- **WHEN** пользователь отправляет форму с корректной почтой
  и паролем «  AbC123  »
- **THEN** тестовый обработчик получает пароль «  AbC123  »
  с сохранением регистра и всех пробелов

  ### Requirement: Исправление ошибок полей

До первой попытки отправки система MUST NOT показывать
ошибки полей.

После попытки отправки поле с ошибкой SHALL повторно
проверяться при изменении его значения. Сообщение SHALL
исчезать, когда значение становится корректным.

#### Scenario: Первое открытие формы

- **WHEN** пользователь открывает форму
- **THEN** сообщения об ошибках полей не отображаются

#### Scenario: Исправление почты

- **GIVEN** под полем почты отображается ошибка
- **WHEN** пользователь вводит корректную почту
- **THEN** ошибка почты исчезает без повторной отправки формы

#### Scenario: Заполнение пароля

- **GIVEN** под пустым полем пароля отображается
  «Обязательное поле»
- **WHEN** пользователь вводит непустой пароль
- **THEN** ошибка пароля исчезает без повторной отправки формы

### Requirement: Ожидание результата отправки

Корректная отправка SHALL запускать обработчик и состояние ожидания.
До его завершения кнопка MUST быть заблокирована, повторная
отправка запрещена, поля доступны только для чтения.

Кнопка SHALL сохранять размер и доступное имя «Войти»,
показывать индикатор без видимого текста и иметь aria-busy="true".

После результата или исключения ожидание SHALL завершаться:
кнопка доступна с текстом «Войти», индикатор скрыт,
aria-busy снят или false, поля редактируются.

#### Scenario: Отправка корректной формы

- **WHEN** пользователь отправляет форму с корректными полями
- **THEN** тестовый обработчик вызывается один раз
- **AND** кнопка заблокирована и показывает индикатор загрузки
  без видимого текста
- **AND** доступное имя кнопки остаётся «Войти»
- **AND** кнопка имеет aria-busy="true"
- **AND** значения полей сохранены, поля доступны только для чтения

#### Scenario: Повторная отправка во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **WHEN** пользователь пытается повторно отправить форму
  кнопкой или клавишей Enter
- **THEN** дополнительный вызов обработчика не происходит

#### Scenario: Изменение полей во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **WHEN** пользователь пытается изменить почту или пароль
- **THEN** значения полей не изменяются

#### Scenario: Завершение ожидания

- **WHEN** тестовый обработчик завершает работу
  с результатом успеха или ошибки либо с исключением
- **THEN** состояние ожидания завершается
- **AND** кнопка снова доступна и отображает «Войти»
- **AND** индикатор загрузки скрыт
- **AND** aria-busy снят или равен "false"
- **AND** поля снова доступны для редактирования

### Requirement: Ошибка отправки

При неверных учётных данных система SHALL показывать
«Неверная почта или пароль», при технической ошибке
или исключении — «Не удалось войти. Попробуйте ещё раз.».

Сообщение SHALL отображаться перед кнопкой в области
aria-live="polite" без перевода фокуса и сдвига кнопки.
Место под сообщение MUST быть зарезервировано.

Ошибка MUST оставаться видимой после завершения ожидания
и очищаться при начале новой корректной отправки.

#### Scenario: Неверные учётные данные

- **WHEN** тестовый обработчик возвращает результат
  «неверные учётные данные»
- **THEN** перед кнопкой отображается
  «Неверная почта или пароль»
- **AND** состояние ожидания завершается

#### Scenario: Техническая ошибка

- **WHEN** тестовый обработчик возвращает техническую ошибку
  или завершается с исключением
- **THEN** перед кнопкой отображается
  «Не удалось войти. Попробуйте ещё раз.»
- **AND** состояние ожидания завершается

#### Scenario: Повторная отправка после ошибки

- **GIVEN** отображается общая ошибка предыдущей отправки
- **WHEN** пользователь повторно отправляет корректную форму
- **THEN** предыдущее общее сообщение исчезает
- **AND** форма переходит в состояние ожидания

### Requirement: Локальный тестовый обработчик

Тестовый обработчик SHALL позволять воспроизводить
успешный результат, неверные учётные данные
и техническую ошибку без обращения к API.

Результат SHALL задаваться настройкой обработчика,
а не специальными значениями почты или пароля.
Обработчик MUST NOT проверять настоящие учётные данные,
создавать сессию или сохранять пароль.

#### Scenario: Выбор тестового результата

- **GIVEN** для обработчика настроен один из тестовых результатов
- **WHEN** пользователь отправляет корректно заполненную форму
- **THEN** обработчик возвращает настроенный результат
  независимо от конкретных значений почты и пароля

#### Scenario: Ожидание ответа

- **GIVEN** результат тестовой отправки ещё не получен
- **WHEN** форма ожидает завершения обработчика
- **THEN** сохраняется состояние ожидания
  до получения результата или исключения

### Requirement: Доступность ошибок полей

Каждое поле SHALL иметь связанную с ним текстовую подпись.
Поле с ошибкой MUST иметь aria-invalid="true"
и быть связано с текстом ошибки через aria-describedby.

После исправления ошибки признак невалидности
и связь с исчезнувшим сообщением SHALL удаляться.

#### Scenario: Поле содержит ошибку

- **WHEN** под полем отображается сообщение об ошибке
- **THEN** поле имеет aria-invalid="true"
- **AND** aria-describedby указывает на сообщение этого поля

#### Scenario: Ошибка исправлена

- **WHEN** значение поля становится корректным
- **THEN** сообщение об ошибке исчезает
- **AND** aria-invalid снят или равен "false"
- **AND** поле больше не ссылается на исчезнувшее сообщение
