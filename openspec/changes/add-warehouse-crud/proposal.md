# Proposal

## Why

Web нужен минимальный настоящий API, чтобы пользователь мог сохранять свои
склады в PostgreSQL. Сейчас API хранит только пользователей, а страница
«Мои склады» намеренно показывает локальное пустое состояние и не запрашивает
данные.

## What Changes

- Добавляется сущность склада с UUID, именем, владельцем-пользователем и
  системными метками времени; владелец определяется только из аутентификации.
- Добавляется защищённый HTTP CRUD: создание, список собственных складов,
  получение, переименование и удаление.
- Для первого этапа предлагается единственное редактируемое поле `name`:
  после удаления крайних пробелов оно обязательно и содержит от 1 до 100
  символов. Карта, роботы, станции, задания и участники склада не добавляются.
- Предлагаемый контракт: `POST` и `GET /warehouses`, а также
  `GET`, `PATCH`, `DELETE /warehouses/:uuid`. Список возвращается без
  пагинации, от новых к старым; отсутствующий, чужой и повторно удалённый
  склад возвращают единый `404`.
- Миграция Prisma, unit/integration/e2e-тесты и README API дополняются так,
  чтобы CRUD проверялся на отдельной тестовой БД и воспроизводился Web.

Перед реализацией представители Web и человек-ревьюер должны подтвердить
поля, маршруты, статусы и формат ошибок. Формат `401` и оболочка ошибок
используют согласованный контракт авторизации из #39/#40; эта задача не
создаёт временную передачу идентификатора пользователя в теле запроса.

## Capabilities

### New Capabilities

- `warehouse-management`: хранение и HTTP-управление личными складами,
  включая валидацию, владение и изоляцию данных пользователей.

### Modified Capabilities

Нет. `user-account` не меняет требования к данным учётной записи, а
`warehouses-page` остаётся статичной страницей до отдельной задачи подключения
Web к API.

## Impact

- API: Prisma schema и миграция, новый NestJS-модуль складов, защищённые
  маршруты, проверки и документация `apps/api/README.md`.
- Тесты: unit, integration и e2e; e2e переводятся на выделенную
  `TEST_DATABASE_URL`, а не прикладную `DATABASE_URL`.
- Зависимость: защищённые endpoint и e2e требуют готового механизма текущего
  пользователя из #39/#40. Авторизация, Web, Simulation, Redis, очереди и
  WebSocket в этот change не входят.
