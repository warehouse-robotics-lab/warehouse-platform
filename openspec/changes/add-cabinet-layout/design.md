# Design

## Context

Мотивация и объём — в `proposal.md`, требования — в `specs/`.

Текущее состояние `apps/web`:

- Next.js 16 (App Router), React 19, Tailwind CSS 4, shadcn/ui в стиле `base-nova`
  на `@base-ui/react`. CLI `shadcn` уже в зависимостях пакета.
- FSD: маршруты в `src/app` подключают страницы из `src/_pages`, UI-kit — в `src/shared`
  (`apps/web/README.md`). Слоя `widgets` пока нет. Из компонентов shadcn есть только `Button`.
- Тема — значения shadcn по умолчанию (нейтральная палитра в `oklch`). На `<html>`
  стоит класс `dark`, поэтому приложение отображается в тёмной теме. Шрифт — Geist.
- Инструментов для тестов в `apps/web` нет.

Макет: `design/warehouse-platform.pen`, ревизия `7419145`, фреймы `Ca1Ii` (1440px)
и `AFo3y` (390px). Порядок работы — [ADR-002](../../../docs/adr/002-ai-development-workflow.md)
с адаптацией для этой задачи (см. `tasks.md`).

## Goals / Non-Goals

**Goals:**

- Каркас кабинета, который следующие разделы используют без изменений: новая страница
  добавляет маршрут в группу кабинета и пункт в список навигации.
- Шапка, которую может переиспользовать экран входа (#18): в макете входа та же шапка.
- Заготовка под будущее сворачивание sidebar без переделки разметки.

**Non-Goals:**

- Настройка линтера правил FSD и инструментов тестирования.
- Тёмная тема и переключатель темы.
- Изменение сгенерированных компонентов shadcn сверх необходимого (см. решение 4).

## Decisions

### 1. Структура по FSD

```text
src/app/(cabinet)/layout.tsx             # каркас для всех страниц кабинета
src/app/(cabinet)/warehouses/page.tsx    # подключает WarehousesPage
src/_pages/warehouses/                   # страница «Мои склады»: заголовок и пустое состояние
src/widgets/app-header/                  # шапка с названием продукта
src/widgets/cabinet-layout/              # навигация (sidebar и полоса) и область содержимого
  config/navigation.ts                   # список разделов: адрес, подпись, иконка
  lib/is-active-path.ts                  # чистая функция: активен ли раздел для адреса
src/shared/ui/                           # sidebar, empty и их зависимости из реестра shadcn
```

- **Группа маршрутов `(cabinet)`** не меняет адрес: страница доступна по `/warehouses`.
  Её `layout.tsx` применяется ко всем будущим страницам кабинета. Экран входа (#18)
  будет вне группы и каркас не получит.
- **Шапка — отдельный виджет.** В макете входа используется та же шапка. FSD запрещает
  импорт между слайсами одного слоя, поэтому шапка не может жить внутри
  `cabinet-layout`, если её возьмёт страница входа.
- **Шапку и каркас соединяет `layout.tsx` группы:** `<CabinetLayout header={<AppHeader />}>`.
  Виджет каркаса принимает шапку через слот и не импортирует соседний виджет.
  Альтернатива — `cabinet-layout` импортирует `app-header` напрямую — нарушает правило
  FSD об импортах внутри слоя.
- **Правило README уточняется.** Сейчас `src/app` «только подключает страницы».
  Добавляется: `layout.tsx` групп маршрутов собирает каркас из виджетов.
  Правило обновляется в `apps/web/README.md`.

### 2. Навигация: ссылки и активность по адресу

- **Пункт — ссылка Next.js (`Link`),** отрисованная через `SidebarMenuButton`
  (проп `render`). Ссылка, а не кнопка, потому что пункт меняет адрес: его можно
  открыть в новой вкладке, а вспомогательные технологии объявляют его как ссылку.
- **Активный пункт вычисляется из `usePathname()`:** адрес совпадает с `href` или
  начинается с `href + "/"`. Состояние выбора не хранится, поэтому после перехода
  по ссылке, обновления страницы или кнопки «Назад» подсветка всегда соответствует адресу.
  Альтернатива — хранить выбранный пункт в состоянии — расходится с адресом и отвергнута.
- **`aria-current="page"` ставится явно:** `SidebarMenuButton` сам выставляет только
  `data-active`.
- **Клиентский компонент только один** — список навигации (ему нужен `usePathname`).
  Шапка, каркас и страница остаются серверными компонентами.

### 3. Sidebar из shadcn с `collapsible="none"`

- **Используется `Sidebar` с `collapsible="none"`:** статичная панель, без сворачивания
  и выдвижной панели. Сворачивание запланировано: тогда достаточно сменить значение
  на `"icon"` или `"offcanvas"`, разметка и стили пунктов не меняются. Цвета берутся
  из переменных `sidebar-*`.
- **Ширина 240px** задаётся переменной `--sidebar-width: 15rem` в `style` у
  `SidebarProvider` (по умолчанию 16rem).
- **`SidebarProvider` оборачивает область под шапкой,** а не всю страницу: шапка
  в макете лежит над панелью. Высоту обёртки по умолчанию (`min-h-svh`) переопределяем,
  чтобы область под шапкой занимала остаток экрана.
- **Полоса для узкой раскладки — свой компонент.** Это тот же список
  `SidebarMenu` / `SidebarMenuButton`, но горизонтальный, внутри того же провайдера.
  Пункты и стили общие. Мобильный режим Sidebar (выдвижная панель `Sheet`) не подходит:
  в макете полоса, а меню для узкого экрана не согласовано.
- **Высота пунктов:** 36px в широкой раскладке и 44px в узкой задаются через `className`
  (по умолчанию у `SidebarMenuButton` 32px). Кольцо фокуса дополняется отступом 2px
  по правилу макета.
- Альтернатива — своя разметка без shadcn — проще сейчас, но при сворачивании
  её пришлось бы заменить.

### 4. Компоненты shadcn: установка без ручных правок

- **Установка — CLI из зависимостей пакета:**
  `pnpm --filter @warehouse/web exec shadcn add sidebar empty`. Файлы попадают по алиасам
  `components.json`: `src/shared/ui`, хук `use-mobile` — в `src/shared/lib/hooks`.
- **Дополнительно реестр приносит `input`, `separator`, `sheet`, `skeleton`, `tooltip`.**
  Существующий `button.tsx` не перезаписывается.
- **Сгенерированные файлы не правятся.** Отличия от макета задаются через `className`
  в месте использования. Так компоненты проще обновлять командой `shadcn`.
- **Пустое состояние — `Empty` из shadcn:** `EmptyHeader`, `EmptyTitle`, `EmptyDescription`,
  без `EmptyMedia` и `EmptyContent`. Под макет переопределяются размеры текста
  и ограничение ширины заголовка (`max-w-sm`). `Empty` по умолчанию растягивается
  на свободную высоту и центрирует содержимое — это совпадает с макетом.

### 5. Тема, шрифт и типографика

- **Значения переменных** из `spec ui-theme` записываются в блок `:root` файла
  `globals.css` в hex, как в макете, чтобы их было легко сверить. Переменные, которых
  нет в макете (`secondary`, `popover`, `chart-*`), не меняются.
- **Класс `dark` удаляется с `<html>`.** Блок `.dark` остаётся без изменений и не применяется.
  Вариант `dark` в Tailwind объявлен через класс, а не через системную настройку,
  поэтому тёмная тема ОС на приложение не влияет.
- **Шрифт Inter** подключается через `next/font/google` с наборами `latin` и `cyrillic`.
  Geist Mono для `--font-mono` остаётся: моноширинный шрифт в макете не задан.
- **Размеры текста.** Макет задаёт заголовок 28/36 и раздел 18/26. В шкале Tailwind
  таких нет (`text-3xl` — 30/36, `text-lg` — 18/28). Поэтому в `@theme` добавляются токены
  `--text-title` и `--text-section` с высотой строки. Основной текст 14/20 — это `text-sm`.
  Отступы макета (4, 8, 12, 16, 24, 32px) совпадают со шкалой Tailwind. Радиус 10px
  совпадает с текущим `--radius`.

### 6. Брейкпоинт `desktop` — 391px

- **В `@theme` объявляется `--breakpoint-desktop: 391px`.** Базовые стили описывают
  узкую раскладку, классы с префиксом `desktop:` — широкую.
- **Значение 391px** — решение для этой задачи: «390px — узкая раскладка, больше —
  широкая» по ширинам фреймов макета. Сам макет порог не выбирает. Значение хранится
  в одном месте.

## Risks / Trade-offs

- [В широкой раскладке на ширине 391–700px область содержимого рядом с панелью 240px
  узкая] → значение порога записано открытым вопросом. Меняется в одном месте
  (`--breakpoint-desktop`), без переделки разметки.
- [Граница мобильного режима shadcn в JS (`use-mobile`) — 768px, а наш брейкпоинт —
  391px] → при `collapsible="none"` мобильный режим не используется, поэтому
  расхождение сейчас не проявляется. При добавлении сворачивания границы нужно согласовать.
- [`SidebarProvider` регистрирует сочетание Ctrl/Cmd+B для сворачивания и сохраняет
  состояние в cookie `sidebar_state`] → при `collapsible="none"` сочетание видимого
  эффекта не даёт, но записывает cookie. Поведение принимается как есть до задачи
  о сворачивании.
- [Реестр shadcn добавляет компоненты, которые сейчас не используются: `sheet`,
  `tooltip`, `input`, `skeleton`, `separator`] → они нужны `sidebar` и понадобятся
  при сворачивании. Состав файлов проверяется в diff перед коммитом.
- [Смена темы глобальна: главная страница и экран входа (#18) тоже станут светлыми
  с цветами макета] → это ожидаемо: макет — источник истины для цветов. О смене
  предупреждается в PR, чтобы автор #18 учёл её.
- [Без автотестов поведение навигации проверяется только вручную] → сценарии
  спецификаций служат чек-листом ручной проверки. Определение активного пункта
  вынесено в чистую функцию, чтобы покрыть его тестом, когда в `apps/web` появятся
  инструменты тестирования.
