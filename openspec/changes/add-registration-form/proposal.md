# Proposal

## Why

Новому пользователю нужен способ создать учётную запись и сразу попасть в кабинет. Задача —
[issue #41](https://github.com/warehouse-robotics-lab/warehouse-platform/issues/41).
Макет регистрации согласован в PR #70, правила полей описаны в спецификации API (PR #61).
API пока нет, поэтому форма работает на локальном тестовом обработчике, а подключение
`POST /auth/register` выполняется отдельной задачей (F7 в PR #61).

## What Changes

- Страница регистрации по адресу `/register` вне каркаса кабинета: шапка
  «Warehouse Platform», карточка с заголовком «Регистрация», форма и ссылка
  «Уже есть аккаунт? Войти» на `/login`.
- Форма с полями «Имя», «Почта», «Пароль» и кнопкой «Создать аккаунт».
- Клиентская проверка полей по правилам PR #61 (ревизия `7380d19`): обязательность,
  длина имени и пароля в символах Unicode, состав пароля, формат и длина почты.
  Почта и имя нормализуются, пароль передаётся без изменений.
- Ошибки полей под полями и общая ошибка в рамке перед кнопкой. Место под них
  зарезервировано, поэтому поля, кнопка и ссылка не сдвигаются при смене состояний.
- Подсказка с требованиями к паролю: значок «ⓘ» справа от подписи «Пароль».
  Открывается при наведении, по нажатию и с клавиатуры, закрывается по Escape.
- Кнопка показа и скрытия пароля в поле пароля.
- Состояние ожидания с запретом повторной отправки.
- Результаты тестового обработчика: успех, «почта уже зарегистрирована» под полем
  почты и техническая ошибка. Результат и задержка задаются переменными окружения,
  как во входе.
- После успеха — переход на `/warehouses` с заменой записи в истории браузера.
- Общие элементы форм (поле с подписью и строкой ошибки, общая ошибка, кнопка
  отправки с индикатором, поле пароля) выносятся в `shared/ui` для повторного
  использования формой входа.
- Автоматические тесты поведения формы и страницы.

## Capabilities

### New Capabilities

- `registration-form`: страница и форма регистрации — поля, правила проверки и тексты
  ошибок, подсказка к паролю, показ пароля, ожидание, результаты тестового обработчика,
  переходы после успеха и ко входу, настройка обработчика для ручной проверки.

### Modified Capabilities

Нет. Требования `user-account` и `cabinet-layout` не меняются. Спецификация формы
входа (`login-form`, PR #34) ещё не слита и в этом изменении не правится.

## Impact

- **Код `apps/web`:**
  - маршрут `src/app/register/page.tsx`;
  - страница `src/_pages/register`: форма, подсказка к паролю, правила проверки,
    тестовый обработчик и разбор его настроек;
  - общие компоненты в `src/shared/ui`, компонент `popover` из реестра shadcn;
  - шапка — существующий виджет `app-header`.
- **Зависимости:** React Hook Form, Zod, `@hookform/resolvers`, Vitest и Testing Library
  приходят с PR #66 (тесты формы входа). Новых пакетов сверх них не ожидается.
  Тесты и реализация начинаются после слияния #66.
- **Документация:** `apps/web/README.md` (маршрут, переменные окружения, общие
  компоненты), `apps/web/.env.example`.
- **Форма входа:** код не меняется. Перевод входа на общие компоненты, тексты пустых
  полей из макета и ссылка на регистрацию — отдельной правкой после слияния #66
  (согласовано с Таней и Стасом, см. `tasks.md`).
- **API, контракты, сессии:** не затрагиваются.

## Out of Scope

- Подключение `POST /auth/register`, создание сессии, cookie, ответ `429
  REGISTRATION_RATE_LIMITED` и тексты по кодам API (F4, F7 в PR #61).
- Защита маршрутов кабинета и перенаправление вошедшего пользователя со страницы
  регистрации (F5).
- Общие Zod-схемы в `@warehouse/contracts`: правила пока описываются в Web и заменяются
  общими схемами в F2.
- Изменения формы входа: ссылка «Нет аккаунта? Зарегистрироваться», кнопка показа
  пароля, тексты пустых полей, переход после входа.
- Подтверждение почты, повтор пароля, согласие с условиями и другие поля, которых нет
  в макете.
- Тёмная тема.
