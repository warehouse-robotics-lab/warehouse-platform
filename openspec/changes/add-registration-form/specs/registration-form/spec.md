# Spec Delta

## Purpose

Регистрация нового пользователя в Web: страница и форма с полями имени, почты и пароля,
проверка полей по правилам учётных данных, подсказка к паролю, ожидание и результаты
отправки, переход в кабинет после успеха и ко входу.

## ADDED Requirements

### Requirement: Страница регистрации

Страница регистрации SHALL открываться по адресу `/register` вне каркаса кабинета.
Страница SHALL показывать шапку с названием «Warehouse Platform», карточку с заголовком
первого уровня «Регистрация», форму и строку «Уже есть аккаунт? Войти». Навигация
кабинета на странице MUST NOT отображаться.

#### Scenario: Открытие по адресу

- **WHEN** пользователь открывает `/register`
- **THEN** отображаются шапка «Warehouse Platform» и карточка с заголовком «Регистрация»
- **AND** вспомогательные технологии определяют «Регистрация» как заголовок первого уровня
- **AND** навигация кабинета не отображается

#### Scenario: Обновление страницы

- **GIVEN** открыта страница `/register`
- **WHEN** пользователь обновляет страницу
- **THEN** снова отображается форма регистрации без сообщений об ошибках

### Requirement: Состав формы

Форма SHALL содержать по порядку поля «Имя», «Почта», «Пароль» и кнопку «Создать
аккаунт». Каждое поле SHALL иметь видимую подпись, связанную с полем. Других полей форма
MUST NOT содержать. Поле почты SHALL иметь тип email. Пароль при открытии формы SHALL
быть скрыт. Подсказки автозаполнения: имя — `name`, почта — `username`, пароль —
`new-password`.

#### Scenario: Поля и кнопка

- **WHEN** пользователь открывает форму
- **THEN** отображаются поля с доступными именами «Имя», «Почта», «Пароль» в этом порядке
- **AND** отображается кнопка «Создать аккаунт»
- **AND** сообщения об ошибках не отображаются

#### Scenario: Подсказки автозаполнения

- **WHEN** пользователь открывает форму
- **THEN** поле имени имеет `autocomplete="name"`
- **AND** поле почты имеет `type="email"` и `autocomplete="username"`
- **AND** поле пароля имеет `type="password"` и `autocomplete="new-password"`

### Requirement: Начальный фокус

При открытии страницы на экране шириной от 768px фокус SHALL устанавливаться в поле
«Имя», как только форма готова к работе. На более узком экране фокус MUST NOT
устанавливаться в поле автоматически. Если пользователь до готовности формы уже перевёл
фокус на элемент страницы, фокус MUST NOT переноситься. Начальный фокус MUST NOT
вызывать показ ошибок.

#### Scenario: Широкий экран

- **GIVEN** ширина окна 768px или больше
- **WHEN** пользователь открывает `/register`
- **THEN** фокус находится в поле «Имя»
- **AND** сообщения об ошибках не отображаются

#### Scenario: Узкий экран

- **GIVEN** ширина окна 767px или меньше
- **WHEN** пользователь открывает `/register`
- **THEN** ни одно поле формы не находится в фокусе

#### Scenario: Пользователь уже перевёл фокус

- **GIVEN** ширина окна 1440px
- **AND** до готовности формы пользователь перевёл фокус на ссылку «Войти»
- **WHEN** форма становится готова к работе
- **THEN** фокус остаётся на ссылке «Войти»

### Requirement: Проверка до и после первой отправки

До первой попытки отправки система MUST NOT показывать ошибки полей. При отправке
система SHALL проверять все поля. После первой попытки каждое поле SHALL проверяться
при каждом изменении его значения: при некорректном значении сообщение появляется, при
корректном исчезает. При ошибке хотя бы одного поля тестовый обработчик MUST NOT
вызываться.

#### Scenario: Ввод до первой отправки

- **WHEN** пользователь вводит в поле имени «Я» и переходит к следующему полю
- **THEN** сообщения об ошибках не отображаются

#### Scenario: Отправка пустой формы

- **WHEN** пользователь отправляет форму с пустыми полями
- **THEN** под полями отображаются «Укажите имя», «Укажите почту» и «Укажите пароль»
- **AND** тестовый обработчик не вызывается

#### Scenario: Исправление поля

- **GIVEN** после отправки под полем почты отображается «Укажите почту»
- **WHEN** пользователь вводит user@example.com
- **THEN** ошибка почты исчезает без повторной отправки формы

#### Scenario: Корректное поле стало некорректным

- **GIVEN** пользователь уже пытался отправить форму
- **AND** поле имени содержит корректное значение без ошибки
- **WHEN** пользователь удаляет из имени все символы, кроме одного
- **THEN** под полем имени появляется «Минимум 2 символа» без повторной отправки формы

### Requirement: Одно сообщение на поле

Под каждым полем SHALL отображаться не более одного сообщения. Если значение нарушает
несколько правил, SHALL показываться первое нарушение по порядку: обязательность,
длина, состав, занятость почты.

#### Scenario: Короткий и слабый пароль

- **WHEN** пользователь отправляет форму с паролем «abc»
- **THEN** под полем пароля отображается только «Минимум 8 символов»

### Requirement: Правила имени

Перед проверкой и отправкой система SHALL удалять крайние пробелы имени, пробелы между
словами сохраняются. Имя из одних пробелов MUST считаться пустым: «Укажите имя». Длина
после удаления пробелов MUST быть от 2 до 64 символов Unicode включительно, символ
считается по кодовой точке. Короче — «Минимум 2 символа», длиннее — «Максимум 64
символа».

#### Scenario: Имя из пробелов

- **WHEN** пользователь отправляет форму с именем из трёх пробелов
- **THEN** под полем имени отображается «Укажите имя»

#### Scenario: Имя из одного символа

- **WHEN** пользователь отправляет форму с именем «  Я  »
- **THEN** под полем имени отображается «Минимум 2 символа»

#### Scenario: Имя длиннее максимума

- **WHEN** пользователь отправляет форму с именем из 65 символов
- **THEN** под полем имени отображается «Максимум 64 символа»

#### Scenario: Граничные длины имени

- **WHEN** пользователь отправляет форму с именем из 2 или из 64 символов
  и остальными корректными полями
- **THEN** ошибка имени не отображается

#### Scenario: Длина имени в кодовых точках

- **WHEN** пользователь отправляет форму с именем «😀» из одной кодовой точки
- **THEN** под полем имени отображается «Минимум 2 символа»

#### Scenario: Максимальная длина имени в кодовых точках

- **WHEN** пользователь отправляет форму с именем из 64 эмодзи «😀» и остальными
  корректными полями
- **THEN** ошибка имени не отображается

#### Scenario: Нормализация имени

- **WHEN** пользователь отправляет форму с именем «  Анна  Смирнова  »
  и остальными корректными полями
- **THEN** тестовый обработчик получает имя «Анна  Смирнова»

### Requirement: Правила почты

Перед проверкой и отправкой система SHALL удалять крайние пробелы почты и приводить её
к нижнему регистру по правилам `user-account`. Почта из одних пробелов MUST считаться
пустой: «Укажите почту». Непустая почта MUST содержать «@» с непустыми частями до и после
него, MUST NOT содержать пробелов и MUST быть не длиннее 254 символов Unicode после
нормализации, символ считается по кодовой точке. Иначе — «Проверьте формат почты».
Точка в домене MUST NOT требоваться.

#### Scenario: Почта из пробелов

- **WHEN** пользователь отправляет форму с почтой из пробелов
- **THEN** под полем почты отображается «Укажите почту»

#### Scenario: Почта без @

- **WHEN** пользователь отправляет форму с почтой userexample.com
- **THEN** под полем почты отображается «Проверьте формат почты»

#### Scenario: Пустая часть адреса

- **WHEN** пользователь отправляет форму с почтой «user@» или «@example.com»
- **THEN** под полем почты отображается «Проверьте формат почты»

#### Scenario: Пробел внутри адреса

- **WHEN** пользователь отправляет форму с почтой «us er@example.com»
- **THEN** под полем почты отображается «Проверьте формат почты»

#### Scenario: Почта длиннее 254 символов

- **WHEN** пользователь отправляет форму с почтой длиной 255 символов
- **THEN** под полем почты отображается «Проверьте формат почты»

#### Scenario: Допустимые адреса

- **WHEN** пользователь отправляет форму с почтой user@localhost или с почтой длиной
  254 символа и остальными корректными полями
- **THEN** ошибка почты не отображается

#### Scenario: Длина почты после нормализации

- **WHEN** пользователь отправляет форму с почтой из 254 символов, перед которой и после
  которой стоят по два пробела, и остальными корректными полями
- **THEN** ошибка почты не отображается
- **AND** тестовый обработчик получает почту из 254 символов без пробелов

#### Scenario: Длина почты в кодовых точках

- **WHEN** пользователь отправляет форму с почтой из 254 кодовых точек, часть которых —
  эмодзи «😀», и остальными корректными полями
- **THEN** ошибка почты не отображается

#### Scenario: Нормализация почты

- **WHEN** пользователь отправляет форму с почтой «  Anna@Example.COM  »
  и остальными корректными полями
- **THEN** тестовый обработчик получает почту anna@example.com

### Requirement: Длина пароля

Пустым MUST считаться только пароль нулевой длины: «Укажите пароль». Пароль MUST
содержать от 8 до 36 символов Unicode включительно, символ считается по кодовой точке.
Короче — «Минимум 8 символов», длиннее — «Максимум 36 символов». Поле MUST NOT
ограничивать длину ввода: лишние символы не отбрасываются, а приводят к ошибке.

#### Scenario: Пароль не заполнен

- **WHEN** пользователь отправляет форму с пустым паролем
- **THEN** под полем пароля отображается «Укажите пароль»

#### Scenario: Пароль короче минимума

- **WHEN** пользователь отправляет форму с паролем «Ab1!efg» из 7 символов
- **THEN** под полем пароля отображается «Минимум 8 символов»

#### Scenario: Пароль длиннее максимума

- **WHEN** пользователь вводит пароль из 40 символов, удовлетворяющий правилам состава,
  и отправляет форму
- **THEN** поле содержит все 40 символов
- **AND** под полем пароля отображается «Максимум 36 символов»

#### Scenario: Граничные длины пароля

- **WHEN** пользователь отправляет форму с паролем из 8 или из 36 символов,
  удовлетворяющим правилам состава, и остальными корректными полями
- **THEN** ошибка пароля не отображается

#### Scenario: Длина пароля в кодовых точках

- **WHEN** пользователь отправляет форму с паролем «Ab1!😀😀😀» из 7 кодовых точек
- **THEN** под полем пароля отображается «Минимум 8 символов»

### Requirement: Состав пароля

Пароль MUST содержать заглавную букву, строчную букву, цифру и специальный символ.
Буквы любого алфавита учитываются. Специальным MUST считаться любой символ, кроме
буквы, цифры и пробела. При нарушении SHALL отображаться «Пароль не соответствует
требованиям».

#### Scenario: Не хватает одного вида символов

- **WHEN** пользователь отправляет форму с паролем Abcdefg! без цифры, abcdef1! без
  заглавной буквы, ABCDEF1! без строчной буквы или Abcdefg1 без специального символа
- **THEN** под полем пароля отображается «Пароль не соответствует требованиям»

#### Scenario: Пробел не считается специальным символом

- **WHEN** пользователь отправляет форму с паролем «Abcdef 12»
- **THEN** под полем пароля отображается «Пароль не соответствует требованиям»

#### Scenario: Пароль из пробелов

- **WHEN** пользователь отправляет форму с паролем из восьми пробелов
- **THEN** под полем пароля отображается «Пароль не соответствует требованиям»

#### Scenario: Кириллический пароль

- **WHEN** пользователь отправляет форму с паролем «Пароль-1» и остальными корректными
  полями
- **THEN** ошибка пароля не отображается

### Requirement: Передача пароля без изменений

Система MUST передавать пароль тестовому обработчику без изменения регистра, удаления
пробелов и других преобразований.

#### Scenario: Пароль с крайними пробелами

- **WHEN** пользователь отправляет форму с паролем «  Ab1!def  » и остальными
  корректными полями
- **THEN** тестовый обработчик получает пароль «  Ab1!def  » с сохранением регистра
  и всех пробелов

### Requirement: Доступность ошибок полей

Сообщение об ошибке поля SHALL отображаться под полем со значком «!» в круге, как в макете. Поле с ошибкой
MUST иметь `aria-invalid="true"` и ссылаться на текст ошибки через `aria-describedby`.
После исправления признак невалидности и ссылка на исчезнувшее сообщение SHALL
удаляться. Значок MUST NOT озвучиваться отдельно от текста.

#### Scenario: Поле содержит ошибку

- **WHEN** под полем отображается сообщение об ошибке
- **THEN** поле имеет `aria-invalid="true"`
- **AND** `aria-describedby` поля указывает на сообщение этого поля

#### Scenario: Ошибка исправлена

- **WHEN** значение поля становится корректным
- **THEN** сообщение об ошибке исчезает
- **AND** `aria-invalid` снят или равен "false"
- **AND** поле больше не ссылается на исчезнувшее сообщение

### Requirement: Подсказка к паролю

Справа от подписи «Пароль», в той же строке сразу после текста, SHALL располагаться кнопка со значком «ⓘ» и доступным именем
«Требования к паролю». Подсказка SHALL перечислять требования: от 8 до 36 символов,
заглавная и строчная буквы, цифра, специальный символ (пробел не считается). Поле
пароля SHALL быть связано с текстом требований через `aria-describedby` независимо от
того, открыта ли подсказка.

#### Scenario: Значок подсказки

- **WHEN** пользователь открывает форму
- **THEN** справа от подписи «Пароль» в той же строке отображается кнопка «Требования к паролю»
  со значком «ⓘ»
- **AND** подсказка закрыта

#### Scenario: Требования доступны из поля пароля

- **GIVEN** подсказка закрыта
- **WHEN** фокус находится в поле пароля
- **THEN** `aria-describedby` поля пароля указывает на текст требований к паролю

### Requirement: Открытие подсказки к паролю

Подсказка SHALL открываться при наведении указателя мыши на значок, по нажатию на значок
на сенсорном экране и по Enter или пробелу, когда значок в фокусе. Переход фокуса на
значок без нажатия клавиш MUST NOT открывать подсказку.

#### Scenario: Наведение указателя

- **WHEN** пользователь наводит указатель мыши на значок «ⓘ»
- **THEN** открывается подсказка с требованиями к паролю

#### Scenario: Нажатие на сенсорном экране

- **WHEN** пользователь нажимает на значок «ⓘ» на сенсорном экране
- **THEN** открывается подсказка с требованиями к паролю

#### Scenario: Открытие с клавиатуры

- **GIVEN** значок «ⓘ» в фокусе после перехода клавишей Tab
- **AND** подсказка закрыта
- **WHEN** пользователь нажимает Enter или пробел
- **THEN** открывается подсказка с требованиями к паролю

### Requirement: Закрытие подсказки к паролю

Подсказка SHALL закрываться по Escape, повторному нажатию на значок на сенсорном экране,
повторному Enter или пробелу на значке и по нажатию вне подсказки. Открытая наведением
подсказка SHALL закрываться, когда указатель покидает значок и подсказку, и MUST
оставаться открытой, пока указатель над ней. После закрытия по Escape фокус SHALL
оказаться на значке, если до открытия он был на значке.

#### Scenario: Закрытие по Escape

- **GIVEN** подсказка открыта с клавиатуры
- **WHEN** пользователь нажимает Escape
- **THEN** подсказка закрывается
- **AND** фокус находится на значке «ⓘ»

#### Scenario: Указатель уходит

- **GIVEN** подсказка открыта наведением указателя
- **WHEN** указатель перемещается со значка на подсказку, а затем за её пределы
- **THEN** подсказка остаётся открытой, пока указатель над ней
- **AND** закрывается после ухода указателя

#### Scenario: Нажатие вне подсказки

- **GIVEN** подсказка открыта нажатием на сенсорном экране
- **WHEN** пользователь нажимает на свободное место страницы
- **THEN** подсказка закрывается

### Requirement: Повторное открытие подсказки после Escape

После закрытия подсказки по Escape наведение MUST NOT снова открывать её, пока указатель
не уйдёт со значка «ⓘ». После ухода указателя и возврата на значок наведение SHALL снова
открывать подсказку. Нажатие на значок, Enter и пробел SHALL открывать её сразу, без
ухода указателя.

#### Scenario: Escape после открытия наведением

- **GIVEN** подсказка открыта наведением указателя на значок «ⓘ»
- **WHEN** пользователь нажимает Escape и двигает указатель, не уводя его со значка
- **THEN** подсказка закрывается и остаётся закрытой

#### Scenario: Возврат указателя на значок

- **GIVEN** подсказка закрыта по Escape после открытия наведением
- **WHEN** указатель уходит со значка «ⓘ» и возвращается на него
- **THEN** подсказка снова открывается

#### Scenario: Открытие нажатием или с клавиатуры после Escape

- **GIVEN** подсказка закрыта по Escape, указатель остаётся над значком «ⓘ»
- **WHEN** пользователь нажимает на значок, Enter или пробел
- **THEN** подсказка открывается без ухода указателя со значка

### Requirement: Расположение подсказки к паролю

Подсказка SHALL открываться над подписью «Пароль». Если над подписью не хватает места
в окне, подсказка SHALL открываться сразу под полем пароля. Открытая подсказка MUST NOT
перекрывать поле пароля ни в одном из положений и MUST NOT сдвигать элементы формы.
Под полем подсказка может закрывать строку ошибки пароля, пока открыта. На ширине
экрана 390px текст подсказки MUST помещаться в окне без обрезания и горизонтальной
прокрутки страницы.

#### Scenario: Подсказка на узком экране

- **GIVEN** ширина окна 390px, страница не прокручена
- **WHEN** пользователь открывает подсказку
- **THEN** подсказка отображается над подписью «Пароль» и не перекрывает поле пароля
- **AND** текст подсказки виден целиком
- **AND** поля, кнопка и ссылка не сдвигаются

#### Scenario: Подсказка после прокрутки

- **GIVEN** ширина окна 390px
- **AND** страница прокручена так, что подпись «Пароль» находится у верхнего края окна
- **WHEN** пользователь открывает подсказку
- **THEN** подсказка отображается сразу под полем пароля и не перекрывает его
- **AND** текст подсказки виден целиком
- **AND** поля, кнопка и ссылка не сдвигаются

### Requirement: Показ и скрытие пароля

В поле пароля SHALL быть кнопка показа пароля. Пока пароль скрыт, её доступное имя —
«Показать пароль», пока показан — «Скрыть пароль». Нажатие SHALL переключать
отображение пароля без изменения значения, фокус остаётся на кнопке. Кнопка SHALL быть
доступна с клавиатуры и во время ожидания результата отправки.

#### Scenario: Показ пароля

- **GIVEN** в поле пароля введено Sklad-2026, пароль скрыт
- **WHEN** пользователь нажимает «Показать пароль»
- **THEN** поле показывает Sklad-2026 открытым текстом
- **AND** кнопка называется «Скрыть пароль» и остаётся в фокусе

#### Scenario: Скрытие пароля

- **GIVEN** пароль показан
- **WHEN** пользователь нажимает «Скрыть пароль»
- **THEN** пароль снова скрыт, значение поля не изменилось
- **AND** кнопка называется «Показать пароль»

### Requirement: Работа с клавиатуры

Порядок перехода клавишей Tab SHALL быть: «Имя», «Почта», «Требования к паролю»,
«Пароль», «Показать пароль», «Создать аккаунт», «Войти». Enter в полях «Имя», «Почта» и
«Пароль» SHALL отправлять форму. Каждый элемент в фокусе SHALL иметь видимое кольцо фокуса.

#### Scenario: Порядок перехода

- **WHEN** пользователь последовательно нажимает Tab, начиная с поля «Имя»
- **THEN** фокус проходит элементы в установленном порядке
- **AND** у каждого элемента в фокусе видно кольцо фокуса

#### Scenario: Отправка клавишей Enter

- **GIVEN** все поля заполнены корректно
- **WHEN** пользователь нажимает Enter в поле «Имя», «Почта» или «Пароль»
- **THEN** форма отправляется

### Requirement: Ожидание результата отправки

Корректная отправка SHALL вызывать тестовый обработчик один раз и запускать ожидание.
До результата кнопка MUST быть заблокирована: нажатие не отправляет форму, кнопка имеет
`aria-disabled="true"` и остаётся доступной для фокуса. Поля доступны только для чтения
и сохраняют значения. На экране кнопка SHALL показывать только спиннер, как в макете,
без текста и сохранять размер. Для вспомогательных технологий кнопка SHALL по-прежнему
называться «Создать аккаунт» и иметь `aria-busy="true"`.

#### Scenario: Отправка корректной формы

- **WHEN** пользователь отправляет форму с корректными полями
- **THEN** тестовый обработчик вызывается один раз
- **AND** на экране кнопка заблокирована и показывает только спиннер, без текста
- **AND** для вспомогательных технологий кнопка называется «Создать аккаунт»
  и имеет `aria-busy="true"` и `aria-disabled="true"`
- **AND** значения полей сохранены, поля доступны только для чтения

#### Scenario: Изменение полей во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **WHEN** пользователь пытается изменить имя, почту или пароль
- **THEN** значения полей не изменяются

### Requirement: Защита от повторной отправки

Повторная отправка до результата тестового обработчика MUST NOT вызывать обработчик.
Это относится и ко второй отправке, сделанной до того, как экран показал ожидание.

#### Scenario: Повторная отправка во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **WHEN** пользователь пытается повторно отправить форму кнопкой или клавишей Enter
- **THEN** дополнительный вызов обработчика не происходит

#### Scenario: Две отправки до обновления экрана

- **WHEN** пользователь дважды подряд отправляет корректную форму до того, как экран
  показал ожидание, например двойным нажатием на кнопку или двумя быстрыми Enter
- **THEN** тестовый обработчик вызывается один раз

### Requirement: Фокус во время ожидания

Начало ожидания MUST NOT переносить фокус. Если форму отправили с кнопки, фокус SHALL
оставаться на кнопке. Если форму отправили клавишей Enter из поля, фокус SHALL
оставаться в этом поле.

#### Scenario: Отправка кнопкой с клавиатуры

- **GIVEN** все поля заполнены корректно, фокус на кнопке «Создать аккаунт»
- **WHEN** пользователь нажимает Enter или пробел
- **THEN** во время ожидания фокус остаётся на кнопке

#### Scenario: Отправка клавишей Enter из поля

- **GIVEN** все поля заполнены корректно, фокус в поле «Пароль»
- **WHEN** пользователь нажимает Enter
- **THEN** во время ожидания фокус остаётся в поле «Пароль»

### Requirement: Завершение ожидания после ошибки

После результата «почта уже зарегистрирована», технической ошибки или исключения
обработчика ожидание SHALL завершаться: кнопка доступна и показывает «Создать аккаунт»,
спиннер скрыт, `aria-busy` и `aria-disabled` сняты или равны "false", поля снова
редактируются.

#### Scenario: Ожидание завершено

- **WHEN** тестовый обработчик возвращает ошибку или завершается с исключением
- **THEN** кнопка доступна и показывает «Создать аккаунт»
- **AND** спиннер скрыт, `aria-busy` и `aria-disabled` сняты или равны "false"
- **AND** поля доступны для редактирования

### Requirement: Фокус после ошибки отправки

После технической ошибки или исключения обработчика форма MUST NOT переносить фокус.
Он остаётся на элементе, где находится в момент результата, в том числе там, куда
пользователь перешёл клавишей Tab во время ожидания. Фокус переносится только при
результате «почта уже зарегистрирована».

#### Scenario: Повтор с кнопки после технической ошибки

- **GIVEN** пользователь отправил форму клавишей Enter на кнопке «Создать аккаунт»
- **WHEN** тестовый обработчик возвращает техническую ошибку
- **THEN** фокус остаётся на кнопке
- **AND** повторное нажатие Enter снова отправляет форму

#### Scenario: Повтор из поля после технической ошибки

- **GIVEN** пользователь отправил форму клавишей Enter из поля «Пароль»
- **WHEN** тестовый обработчик возвращает техническую ошибку
- **THEN** фокус остаётся в поле «Пароль»

#### Scenario: Уход клавишей Tab во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **AND** пользователь перешёл клавишей Tab на ссылку «Войти»
- **WHEN** тестовый обработчик возвращает техническую ошибку
- **THEN** фокус остаётся на ссылке «Войти»

### Requirement: Почта уже зарегистрирована

При результате «почта уже зарегистрирована» под полем почты SHALL отображаться «Эта
почта уже зарегистрирована», а фокус SHALL переходить в поле почты, даже если
пользователь во время ожидания перешёл к другому элементу. Общая ошибка MUST
NOT показываться. Сообщение SHALL исчезать при изменении почты, дальше поле проверяется
по обычным правилам. Повторная отправка без изменений SHALL снова вызывать обработчик.

#### Scenario: Почта занята

- **WHEN** тестовый обработчик возвращает результат «почта уже зарегистрирована»
- **THEN** под полем почты отображается «Эта почта уже зарегистрирована»
- **AND** фокус находится в поле почты
- **AND** общая ошибка не отображается

#### Scenario: Изменение почты после ошибки

- **GIVEN** под полем почты отображается «Эта почта уже зарегистрирована»
- **WHEN** пользователь изменяет почту на другой корректный адрес
- **THEN** сообщение исчезает

#### Scenario: Повторная отправка той же почты

- **GIVEN** под полем почты отображается «Эта почта уже зарегистрирована»
- **WHEN** пользователь отправляет форму без изменений
- **THEN** тестовый обработчик вызывается снова

### Requirement: Общая ошибка отправки

При технической ошибке или исключении обработчика SHALL отображаться «Не удалось создать
аккаунт. Попробуйте ещё раз.» в области перед кнопкой: в рамке со значком «!» в круге. Область
SHALL объявлять сообщение вспомогательным технологиям без перевода фокуса
(`aria-live="polite"`).

#### Scenario: Техническая ошибка

- **WHEN** тестовый обработчик возвращает техническую ошибку или завершается с исключением
- **THEN** перед кнопкой отображается «Не удалось создать аккаунт. Попробуйте ещё раз.»
- **AND** фокус не перемещается

### Requirement: Сохранение общей ошибки

Общая ошибка MUST оставаться видимой при редактировании полей и при отправке формы
с ошибками полей. Она SHALL исчезать только при начале новой корректной отправки.

#### Scenario: Редактирование после общей ошибки

- **GIVEN** отображается общая ошибка
- **WHEN** пользователь изменяет любое поле
- **THEN** общая ошибка остаётся видимой

#### Scenario: Невалидная отправка после общей ошибки

- **GIVEN** отображается общая ошибка
- **WHEN** пользователь отправляет форму с пустым паролем
- **THEN** под паролем отображается «Укажите пароль»
- **AND** общая ошибка остаётся видимой
- **AND** тестовый обработчик не вызывается

#### Scenario: Повторная корректная отправка

- **GIVEN** отображается общая ошибка
- **WHEN** пользователь отправляет корректную форму
- **THEN** общая ошибка исчезает
- **AND** форма переходит в состояние ожидания

### Requirement: Неизменность раскладки

Место под сообщение каждого поля и под общую ошибку SHALL быть зарезервировано.
Появление и исчезновение ошибок, ожидание, открытие подсказки и показ пароля MUST NOT
сдвигать поля, кнопку и ссылку. Раскладка на ширине 1440px и 390px SHALL
соответствовать макету регистрации. Каждое сообщение поля MUST помещаться в одну
строку на ширине 390px.

#### Scenario: Смена состояний

- **WHEN** форма переходит между исходным состоянием, ошибками полей, ожиданием
  и общей ошибкой
- **THEN** положение полей, кнопки и ссылки «Войти» не меняется

#### Scenario: Узкий экран

- **GIVEN** ширина окна 390px
- **WHEN** отображается каждое из сообщений об ошибках полей
- **THEN** сообщение занимает одну строку
- **AND** горизонтальная прокрутка страницы отсутствует

#### Scenario: Соответствие макету

- **WHEN** форма открыта на ширине 1440px или 390px в состояниях макета
- **THEN** отступы, размеры и тексты совпадают с макетом регистрации

### Requirement: Успешная регистрация

При успешном результате форма SHALL один раз вызывать внешний обработчик успеха, а
страница SHALL открывать `/warehouses`, заменяя запись `/register` в истории браузера.
До ухода со страницы форма SHALL оставаться в состоянии ожидания. Тестовый обработчик
MUST NOT создавать сессию.

#### Scenario: Переход в кабинет

- **WHEN** тестовый обработчик возвращает успешный результат
- **THEN** внешний обработчик успеха вызывается один раз
- **AND** открывается `/warehouses`

#### Scenario: Кнопка «Назад» после регистрации

- **GIVEN** пользователь открыл `/register` со страницы `/login` и успешно
  зарегистрировался
- **WHEN** на `/warehouses` пользователь нажимает «Назад» в браузере
- **THEN** открывается `/login`, а не форма регистрации

#### Scenario: Ожидание до перехода

- **GIVEN** тестовый обработчик вернул успешный результат
- **WHEN** страница регистрации ещё отображается
- **THEN** кнопка заблокирована и имеет `aria-busy="true"`
- **AND** повторная отправка не вызывает обработчик

### Requirement: Уход со страницы до результата

Если пользователь покидает страницу регистрации до результата тестового обработчика,
результат MUST NOT обрабатываться: переход на `/warehouses` и показ ошибок не
выполняются.

#### Scenario: Переход ко входу во время ожидания

- **GIVEN** форма ожидает результат тестового обработчика
- **WHEN** пользователь переходит по ссылке «Войти»
- **AND** затем обработчик возвращает успешный результат
- **THEN** остаётся открытой страница `/login`

### Requirement: Переход ко входу

Под кнопкой SHALL отображаться строка «Уже есть аккаунт? Войти», где «Войти» — ссылка на
`/login`, а «Уже есть аккаунт?» — обычный текст. Ссылка SHALL быть доступна во всех
состояниях формы.

#### Scenario: Переход по ссылке

- **WHEN** пользователь нажимает «Войти» мышью или клавишей Enter
- **THEN** открывается `/login`

### Requirement: Локальный тестовый обработчик

Обработчик SHALL воспроизводить успех, «почта уже зарегистрирована» и техническую ошибку
без API. Результат MUST задаваться настройкой, а не значениями полей. Обработчик
получает нормализованные имя и почту и исходный пароль. Обработчик MUST NOT проверять
настоящие данные, создавать сессию и сохранять пароль.

#### Scenario: Выбор тестового результата

- **GIVEN** для обработчика настроен один из тестовых результатов
- **WHEN** пользователь отправляет корректно заполненную форму
- **THEN** обработчик возвращает настроенный результат независимо от значений полей

#### Scenario: Данные для обработчика

- **WHEN** пользователь отправляет корректно заполненную форму
- **THEN** обработчик получает имя, почту и пароль после нормализации, описанной
  в правилах полей

### Requirement: Настройка ручной проверки

В режиме разработки результат SHALL задаваться `NEXT_PUBLIC_REGISTRATION_MOCK_RESULT`:
`success`, `email-taken` или `technical-error`, по умолчанию `success`. Задержка SHALL
задаваться `NEXT_PUBLIC_REGISTRATION_MOCK_DELAY_MS`: целое число от 0 до 10000
миллисекунд, по умолчанию 1500. Настройки применяются после перезапуска сервера
разработки. Переключатели в форме MUST NOT добавляться.

#### Scenario: Настройки отсутствуют

- **GIVEN** настройки результата и задержки не заданы
- **WHEN** пользователь отправляет корректную форму
- **THEN** обработчик возвращает успех после задержки 1500 миллисекунд

#### Scenario: Задан только результат

- **GIVEN** `NEXT_PUBLIC_REGISTRATION_MOCK_RESULT` задан как `email-taken`,
  задержка не задана, сервер разработки перезапущен
- **WHEN** пользователь отправляет корректную форму
- **THEN** обработчик возвращает «почта уже зарегистрирована» после 1500 миллисекунд

#### Scenario: Задана только задержка

- **GIVEN** `NEXT_PUBLIC_REGISTRATION_MOCK_DELAY_MS` задан как 3000,
  результат не задан, сервер разработки перезапущен
- **WHEN** пользователь отправляет корректную форму
- **THEN** обработчик возвращает успех после 3000 миллисекунд

### Requirement: Ошибки настройки тестового обработчика

Значение по умолчанию MUST применяться только к отсутствующей настройке. Пустое или
некорректное значение MUST вызывать ошибку конфигурации: в области общей ошибки SHALL
отображаться «Ошибка настройки тестового обработчика. Проверьте настройки разработки.».
До исправления настроек отправка MUST NOT вызывать обработчик и переход после успеха,
поля проверяются как обычно.

#### Scenario: Неизвестный результат

- **GIVEN** `NEXT_PUBLIC_REGISTRATION_MOCK_RESULT` задан как `succes`,
  сервер разработки перезапущен
- **WHEN** пользователь открывает форму и отправляет корректные данные
- **THEN** в области общей ошибки отображается «Ошибка настройки тестового обработчика.
  Проверьте настройки разработки.»
- **AND** тестовый обработчик не вызывается, переход не выполняется

#### Scenario: Некорректная задержка

- **GIVEN** `NEXT_PUBLIC_REGISTRATION_MOCK_DELAY_MS` задан как -1, 10001, 1.5 или abc,
  сервер разработки перезапущен
- **WHEN** пользователь открывает форму
- **THEN** в области общей ошибки отображается ошибка настройки

#### Scenario: Пустое значение настройки

- **GIVEN** одна из настроек задана пустой строкой, другая корректна,
  сервер разработки перезапущен
- **WHEN** пользователь открывает форму
- **THEN** в области общей ошибки отображается ошибка настройки
- **AND** значение по умолчанию не подставляется вместо пустой строки

#### Scenario: Проверка полей при ошибке настройки

- **GIVEN** отображается ошибка настройки
- **WHEN** пользователь отправляет пустую форму
- **THEN** под полями отображаются сообщения об обязательности
- **AND** ошибка настройки остаётся видимой

### Requirement: Защита пароля

Пароль MUST NOT попадать в адрес страницы, журнал консоли браузера, хранилища браузера
и cookie. До готовности формы к работе поля и кнопка MUST быть недоступны, чтобы браузер
не отправил форму обычной отправкой с данными в адресе.

#### Scenario: После отправки

- **WHEN** пользователь отправляет форму с любым результатом обработчика
- **THEN** адрес страницы не содержит пароль и других значений полей
- **AND** пароль отсутствует в консоли, `localStorage`, `sessionStorage` и cookie

#### Scenario: До готовности формы

- **WHEN** страница ещё не готова к работе после загрузки
- **THEN** поля и кнопка «Создать аккаунт» недоступны
