# Proposal

## Why

Поведение API авторизации уже согласовано и зафиксировано в `openspec/specs/auth-api`,
`openspec/specs/user-credentials` и `openspec/specs/user-session` (change `add-auth-api`,
PR #61). Следующий шаг — дать API и Web один источник схем, типов, кодов ошибок и
правил полей, иначе клиент и сервер начнут дублировать проверки и разойдутся в кодах
нарушений. Change 1 из плана `Workflow follow-up` закрывает именно эту основу.

Change 1 не меняет согласованное поведение. Он реализует контрактный пакет, тесты
контракта и документацию OpenAPI. Redis, фильтр ошибок, CSRF, хеширование, сессии,
guard и HTTP-обработчики остаются в изменениях B1–B9.

## What Changes

- Появляется workspace-пакет `@warehouse/contracts`:
  - Zod-схемы запросов, ответов пользователя и ошибок;
  - экспортируемые TypeScript-типы;
  - справочник кодов ошибок и текстов сообщений;
  - коды нарушений полей и их канонический порядок;
  - правила полей для регистрации и входа, включая нормализацию email, длину в
    кодовых точках и сохранение исходного пароля без изменений.
- Те же схемы используются для генерации OpenAPI через `z.toJSONSchema` (Zod 4), без
  ручного дублирования DTO.
- В `apps/api` подключается Swagger UI и JSON-документ с описанием четырёх адресов
  (`POST /auth/register`, `POST /auth/login`, `POST /auth/logout`,
  `GET /users/current`), их статусов, тел и заголовков по карте контракта. Документ
  описывает статусы и заголовки, но не реализует их поведение — оно остаётся в B1–B9.
  Фиктивные auth-обработчики не добавляются; документация помечается как контракт без
  реализации.
- `apps/api` и `apps/web` подключают пакет через `workspace:*`. Подключение зависимости
  не означает интеграцию форм с API: формы и транспорт остаются в F1–F7.
- Обновляются README затронутых пакетов и приложений, конфигурация сборки, тестов и
  порядок сборки workspace-зависимостей.

## Capabilities

### New Capabilities

Нет. Change не вводит новых требований к поведению: он реализует уже согласованные
требования `auth-api`, `user-credentials` и `user-session`. Поэтому в `.openspec.yaml`
установлено `skip_specs: true`; дельта-спецификации не создаются и история ревью не
копируется.

### Modified Capabilities

Нет. Существующие требования не меняются. Расхождения, найденные при реализации,
оформляются отдельным вопросом и не правятся молча.

## Impact

- **`packages/contracts`:** новый пакет, публичные экспорты, сборка, тесты, README.
- **`apps/api`:** зависимость `@warehouse/contracts`, `@nestjs/swagger`, модуль
  генерации OpenAPI и подключение Swagger в `main.ts`; обработчики авторизации не
  добавляются.
- **`apps/web`:** зависимость `@warehouse/contracts`; публичные типы и схемы доступны
  для будущих F1/F2, но формы и транспорт не подключаются.
- **`pnpm-lock.yaml`:** изменение из-за новых workspace-зависимостей и
  `@nestjs/swagger`.
- **Документация:** README пакета, API и Web; описание `/docs` и `/docs-json`.

## Out of Scope

- Redis, конфигурация B1, CORS/preflight B1, фильтр ошибок и CSRF B2, хеширование B3,
  сессии B4/B5, guard B5, обработчики B6–B8, лимиты B9.
- UI, клиентская проверка F1/F2, подключение форм F3–F7 и транспорт Web → API.
- Выбор ts-rest/tRPC, топология развёртывания, изменение согласованных политик.
- Любая неполная авторизация, доступная пользователям.
