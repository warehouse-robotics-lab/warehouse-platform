# Spec Delta

## Purpose

Жизненный цикл сессии пользователя: создание при входе, хранение на сервере, сроки жизни
и продление, завершение выходом и поведение запроса без действующей сессии.

## ADDED Requirements

### Requirement: Создание сессии

При успешном входе или регистрации система MUST создавать серверную сессию и передавать
клиенту cookie с непрозрачным непредсказуемым идентификатором сессии. Идентификатор MUST
генерироваться как 32 случайных байта в кодировке base64url без символа заполнения.
Идентификатор сессии MUST NOT попадать в тело ответа.

#### Scenario: Сессия создана при входе

- **WHEN** пользователь входит с верными учётными данными
- **THEN** система создаёт сессию и устанавливает cookie с идентификатором сессии
- **AND** тело ответа не содержит идентификатор сессии

#### Scenario: Формат идентификатора сессии

- **WHEN** система создаёт сессию
- **THEN** идентификатор сессии — строка в кодировке base64url без символа заполнения

#### Scenario: Cookie не создаётся при отказе

- **WHEN** вход отклонён из-за неверных учётных данных
- **THEN** cookie сессии не устанавливается

#### Scenario: Сессия создана при регистрации

- **WHEN** пользователь успешно регистрируется
- **THEN** система создаёт сессию и устанавливает cookie с идентификатором сессии

### Requirement: Параметры cookie сессии

Cookie сессии MUST иметь признак `HttpOnly`. Имя cookie, путь и остальные признаки MUST
задаваться конфигурацией; значения по умолчанию — имя `warehouse_session`, путь `/`.
Срок cookie MUST задаваться признаком `Max-Age` и MUST соответствовать меньшему из
остатков двух сроков сессии — неактивности и абсолютного.

#### Scenario: Значения по умолчанию

- **GIVEN** параметры cookie в конфигурации не заданы
- **WHEN** система устанавливает cookie сессии
- **THEN** имя cookie — `warehouse_session`, путь — `/`

#### Scenario: Срок cookie не превышает срок сессии

- **WHEN** система устанавливает или перевыдаёт cookie сессии
- **THEN** `Max-Age` равен меньшему из остатков срока неактивности и абсолютного срока

### Requirement: Сроки жизни сессии

Сессия MUST иметь два срока, заданных конфигурацией: срок неактивности (по умолчанию
24 часа) и абсолютный срок (по умолчанию 7 суток). Сессия MUST прекращаться при
истечении любого из сроков. Обработка запроса с действующей сессией MUST продлевать срок
неактивности и MUST NOT изменять абсолютный срок. Сессия, у которой истёк хотя бы один
из сроков, MUST считаться недействующей.

#### Scenario: Сроки сессии берутся из конфигурации

- **GIVEN** сроки неактивности и абсолютный срок заданы конфигурацией
- **WHEN** создаётся сессия
- **THEN** сессия получает оба срока, отсчитываемых от момента создания

#### Scenario: Продление срока неактивности

- **GIVEN** пользователь выполняет авторизованный запрос
- **WHEN** с момента последнего обращения прошло меньше срока неактивности
- **THEN** система продлевает срок неактивности сессии

#### Scenario: Абсолютный срок не продлевается

- **GIVEN** пользователь активно работает
- **WHEN** с момента создания сессии проходит больше абсолютного срока
- **THEN** система считает сессию недействительной и отвечает `401` с кодом ошибки `UNAUTHENTICATED`

#### Scenario: Срок неактивности истёк

- **GIVEN** с момента последнего обращения прошло больше срока неактивности
- **WHEN** пользователь выполняет запрос с этой сессией
- **THEN** система считает сессию недействительной и отвечает `401` с кодом ошибки `UNAUTHENTICATED`

### Requirement: Перевыдача cookie при продлении

Обработка запроса с действующей сессией MUST перевыдавать cookie сессии со сроком,
равным меньшему из остатков двух сроков, иначе cookie истечёт раньше серверной сессии.

#### Scenario: Cookie перевыдаётся при продлении

- **GIVEN** пользователь выполняет авторизованный запрос
- **WHEN** система продлевает срок неактивности сессии
- **THEN** ответ содержит cookie сессии с `Max-Age`, равным меньшему из остатков двух сроков

### Requirement: Завершение сессии

Выход MUST удалять серверную сессию, после чего запрос с прежней cookie MUST считаться
неавторизованным, и MUST сбрасывать cookie сессии, устанавливая пустое значение и
`Max-Age=0`. Выход MUST быть идемпотентным: выход без cookie и повторный выход MUST
завершаться успехом без ошибки.

#### Scenario: Выход завершает сессию

- **WHEN** авторизованный пользователь выполняет выход
- **THEN** система удаляет сессию на сервере
- **AND** cookie сессии сбрасывается

#### Scenario: Запрос после выхода

- **GIVEN** пользователь вышел из сессии
- **WHEN** он выполняет запрос с прежней cookie
- **THEN** система отклоняет запрос как неавторизованный

#### Scenario: Повторный выход

- **GIVEN** пользователь уже вышел из сессии
- **WHEN** он выполняет выход снова
- **THEN** система отвечает успехом и не сообщает об ошибке

#### Scenario: Выход без cookie

- **WHEN** клиент выполняет выход без cookie сессии
- **THEN** система отвечает успехом и не сообщает об ошибке

### Requirement: Одна сессия на пользователя

У пользователя MUST быть не более одной действующей сессии. При успешном входе прежняя
сессия пользователя MUST удаляться, а новая MUST создаваться. Прежняя cookie после
такого входа MUST переставать давать авторизованный доступ.

#### Scenario: Повторный вход заменяет сессию

- **GIVEN** пользователь вошёл в сессию и выполняет запросы с её cookie
- **WHEN** он входит заново с верными учётными данными
- **THEN** система удаляет прежнюю сессию и создаёт новую
- **AND** запрос с прежней cookie отклоняется как неавторизованный

### Requirement: Поведение неавторизованного запроса

Запрос к закрытому ресурсу без действующей сессии MUST отклоняться ответом `401` с
кодом ошибки `UNAUTHENTICATED`. Отсутствующая cookie, cookie с неизвестным
идентификатором и истёкшая сессия MUST давать одинаковый ответ без данных пользователя.

#### Scenario: Запрос без cookie

- **WHEN** клиент выполняет запрос к закрытому ресурсу без cookie сессии
- **THEN** система отвечает `401` с кодом ошибки `UNAUTHENTICATED`
- **AND** тело ответа не содержит данных пользователя

#### Scenario: Cookie с неизвестным идентификатором

- **WHEN** клиент выполняет запрос с cookie, которой нет на сервере
- **THEN** система отвечает `401` с кодом ошибки `UNAUTHENTICATED`

#### Scenario: Истёкшая сессия

- **GIVEN** срок сессии истёк
- **WHEN** клиент выполняет запрос с этой cookie
- **THEN** система отвечает `401` с кодом ошибки `UNAUTHENTICATED`

### Requirement: Сессия на разных процессах API

Сессия MUST быть доступна всем процессам API: проверка и завершение сессии MUST давать
одинаковый результат на любом процессе.

#### Scenario: Запрос через другой процесс

- **GIVEN** пользователь вошёл в сессию через процесс API A
- **WHEN** тот же пользователь выполняет запрос через процесс API B
- **THEN** процесс API B признаёт сессию действующей и отдаёт данные пользователя

#### Scenario: Выход через другой процесс

- **GIVEN** пользователь вошёл в сессию через процесс API A
- **WHEN** он выходит через процесс API A и выполняет запрос через процесс API B
- **THEN** процесс API B признаёт сессию недействительной и отклоняет запрос

### Requirement: Хранение сессии

Серверная часть сессии MUST храниться в Redis отдельно от данных пользователя.
Идентификатор сессии MUST генерироваться криптографически стойким способом.
Идентификатор сессии MUST NOT записываться в журналы.

#### Scenario: Сессия хранится в Redis

- **WHEN** пользователь входит с верными учётными данными
- **THEN** запись сессии появляется в Redis и содержит идентификатор пользователя и сроки

#### Scenario: Идентификатор сессии не попадает в журнал

- **WHEN** система записывает в журнал результат входа
- **THEN** в записи журнала отсутствует идентификатор сессии
