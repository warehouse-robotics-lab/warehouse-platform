# Design

## Context

См. `proposal.md` и `specs/warehouse-renderer/spec.md`. Сетка и наведение уже есть.
Konva выбран в [ADR-004](../../../docs/adr/004-warehouse-renderer-konva.md). Расчёт движения остаётся в Simulation ([ADR-003](../../../docs/adr/003-module-interaction.md)). Макет объектов не передан, сверка с макетом не применяется.

## Goals / Non-Goals

**Goals:**

- Принять карту и отдать выделенный участок.
- Рисовать три типа объектов в текущем холсте.
- Развести режим редактирования и режим симуляции.
- Рисовать линию будущего пути по переданному `route`.

**Non-Goals:**

- Снимок запуска целиком, камера, инструменты, перетаскивание.
- Проверка клеток, пересечений и запрет правки карты во время запуска. Это делают Web, API и Simulation.
- Типы Konva в публичном API.

## Decisions

### 1. Вход

`mode` равен `"edit"` или `"simulation"`. `map` несёт `gridWidth`, `gridHeight`, `obstacles`, `stations` и `robots`. У станции и робота есть `id` только как ключ. Выбор сообщает `onSelect(cells: Cell[])` только в `"edit"`; в `"simulation"` выбора нет. Выбор контролируется снаружи. Квадрат разворачивается в массив клеток `1×1`. Ширина и высота наружу не передаются. Рамку рисует prop `selection`. Без `map` остаются нынешние `gridWidth` и `gridHeight`.

В `"edit"` рисуются клетки карты, смена клетки мгновенная. В `"simulation"` у робота есть подтверждённая позиция, `route: Cell[]` и необязательный текущий отрезок `{ from, to }`. Линия идёт от позиции по `route` и лежит под роботом. Подряд идущие клетки анимируются к последней. После пропуска отметка не едет через потерянные клетки: известный отрезок проигрывается от `from` к `to`, неизвестный заменяется мгновенным появлением на новой клетке. Длительность переезда на одну клетку равна prop `stepIntervalMs` — интервалу шага симуляции: тем же интервалом приложение публикует следующий снимок. У ядра таймера нет. Renderer свою длительность не подставляет. Компонент рисует переданные клетки и не решает, допустимы ли они. Порядок слоёв: станция ниже робота.

Полный набор намерений из [PR #68](https://github.com/warehouse-robotics-lab/warehouse-platform/pull/68) не копируется: RFC не принят, а [#20](https://github.com/warehouse-robotics-lab/warehouse-platform/issues/20) просит только клетку.

### 2. Указатель и слой

Фигуры объектов не принимают события. Клетку считает сцена, как сейчас для наведения. Один слой, без кэша: фон и сетка, препятствия, станции, линия будущего пути, роботы, рамка выбора, рамка наведения. Цвета — константы пакета; спека требует только различие.

### 3. Проверки

Тесты лежат рядом с компонентом. В пакете нет runner для React, Jest API завязан на Nest. Для этих тестов добавляется Vitest. Сценарии холста проверяются моком `react-konva`.

## Risks / Trade-offs

- [Имена полей снимка в RFC ещё меняются] → снимок в этот вход не входит.
- [Цвета не из макета] → они не часть контракта, пока знаки отличимы.
